3. 校验按内容哈希归档的调试包，使用 `tools/pack_offline_release.py` 生成分段包；刷前确认新固件、设备身份和写入范围及授权。
4. 保留 NVS `0x9000..0xefff`、PHY `0xf000..0xffff`、files `0x700000..0x7fffff`。兼容布局为应用 `0x10000..0x1fffff`、厨房资源 `0x200000..0x6fffff`。合并镜像会填充空隙，保留数据时不能盲目整包刷入。
5. 优先修复菜库初始化的工作量边界：检查 `kc_load` 循环和 `krc_read_body` 的 CRC。按有界批次主动让出 CPU，或采用校验一致的 CRC 实现；仅粗粒度阶段之间延时已复现看门狗。补针对性宿主测试，并多次实机重启复验。
6. 为无声诊断增加只读状态：`sound`、`volume`、`audio_ready`、开机语音触发和混音消费量。保留已存设置；追踪 ES8311/I2S 播放链路后再判断声音恢复。PCM 正常和 API 成功不等于人耳可听。
7. 检查用户确认提示且存档序号增加后为何又恢复时钟丢失。没有可信时钟时，运行中的计时器有意恢复为暂停；确认运行/暂停状态和存档，不删除计时器绕过保护。
8. 随后跑隔离的开机/首页、海鲜两页、超过三次的四菜换组、用料到采购、计时暂停/取消及不自动重启检查。记录堆栈，确认隔离期间存档序号不变，恢复正常模式并关闭串口。

另一台电脑使用上述两个分支的独立工作目录。拉取或切分支前先检查 `git status --short --branch`。没有克隆时，同一个仓库分别用 `--branch codex/offline-kitchen` 克隆固件、用 `--branch codex/kitchen-model` 克隆可编辑内容。先读 `AGENTS.md` 和本交接，再按维护的环境指南准备那台电脑的 ESP-IDF 5.5.3。本机绝对路径与私密测试脚本不会自动出现在另一台电脑。

`experiments/krc_stream/` 的 1000/1500 条实验只是合成索引概念验证，没有制作千道真实菜谱，也没有接入生产界面、推荐或存档。扩展前先读该目录双语 README。
