# 路线图

每个阶段结束都要能验证，负责人在 `HANDOFF.md` 报告：做了什么、实测数据、哪些还没验证。

## 阶段总览

| 阶段 | 目标 | 负责 | 交付物 | 完成标准 |
|---|---|---|---|---|
| **M0 设计** | 架构、规格和分工定下来 | Claude | 本仓库的文档、线框图、菜谱格式、样例菜谱 | 刘东坡确认“待你决定”里的事项 |
| **A1 造型和风格样板** | 定下 NABO 厨房造型、配色和画风 | Codex 出图，刘东坡选 | `costume/` 方案 A/B/C，`style/style_board.png` 样板屏 | 选定造型和样板屏，色表锁定 |
| **D1 菜谱第一批** | 先有 30 道能用的菜 | 刘东坡提供，Claude 整理 | `data/recipes/` 下 30 个 JSON | 全部通过 schema 检查，刘东坡审过 |
| **M1 原型** | 在浏览器里走通全部流程 | Claude | `prototype/index.html`，先用占位图 | 刘东坡在手机上用原型完整做一道菜 |
| **A2 核心美术** | v0.1 所需的全部素材 | Codex、Grok | 4 个核心动作的视频、30 个食材、器皿和汤汁图层、界面套件、吧台背景 | 过 ART_BRIEF 验收清单 |
| **T1 打包管线** | 素材变成固件格式 | Claude | `tools/` 下的抽帧、限色、图层打包、菜谱打包、字体子集 | 解码回来和源图逐像素比对通过；预算表更新 |
| **M2 逻辑模型** | C 版规则和原型一致 | Codex | `kitchen_model.c` 和对拍测试 | 对拍轨迹全部一致；故意改坏规则能被抓到 |
| **M3 渲染** | C 版画面和原型一致 | Codex | 各页面视图、菜品合成 | 宿主渲染 PNG 和原型一致；增量重画和整屏重画一致 |
| **M4 接入固件** | 分出固件仓库，装进工牌 | Codex | `ai-passport-nabo-xiaozhi-kitchen` | 真机验收清单（ARCHITECTURE 第 11 节）通过 |
| **v0.1 发布** | 自己家里能天天用 | Codex 发布，刘东坡验收 | Release 包 | 在自己家厨房连续用一周 |

## 版本内容

| 版本 | 功能 | 美术 | 菜谱 |
|---|---|---|---|
| **v0.1 能用** | 抽菜（单道和搭配）、跟做、3 个计时器、7 天去重、重抽次数 | NABO 待机、颠勺、端盘、守锅；30 个食材；全部器皿和汤汁；界面套件 | 30 道 |
| **v0.2 好用** | 冰箱模式、买菜单、收藏、用量按人数换算 | 补齐 50 个食材；做法和火候图标；冰箱和买菜单界面 | 100 道 |
| **v0.3 好玩** | 图鉴、等级、连续天数、每周挑战 | 敲锅、完成、摇头、偷吃、打瞌睡、升级；徽章；印章；首批招牌菜精绘 | 200 道 |
| **v0.4 联动** | 模式 B 边做边聊；小智存菜谱；MCP 全套工具 | NABO 小头像表情 | 300 道起，可以继续扩充 |
| 之后 | 招牌菜精绘持续增加；可选颠勺节奏小游戏；考虑做成社区独立版 | | |

## 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 模式 B 内存不够 | 不能边做边说话 | v0.1 不依赖它；M4 先做验证；不行就降级成只有步骤卡片 |
| files 分区已被占用或文件系统不合适 | 用户菜谱和记录没地方存 | M4 开工前先核实；备选方案见 ARCHITECTURE 5.2 |
| assets 预算超支 | 素材放不下 | 按 ARCHITECTURE 5.3 的顺序减 |
| 分层合成的菜像“贴纸” | 不够精致 | A1 样板屏里就要验证合成效果；加汤汁底和高光层；招牌菜用精绘图补 |
| 计时铃在厨房听不见 | 菜烧糊 | 真机在油烟机旁实测；铃声频段和重复次数可以调 |
| 菜谱缺字 | 屏幕显示方块 | 打包时检查；用户菜谱写入前检查 |
