## 1. 结论

**一天半做出了一个能装、能用、已公开的首版，美术质量很高。**最大的短板不在工程，而在**菜谱内容**：大约一半菜谱是用模板批量拼出来的，写法也偏向食品安全规范，不像家常菜谱。其次是**首次安装路径没有在真机上走过**，而社区用户恰好全部走这条路。

## 3. 菜谱内容（最需要处理）

新增的检查工具 `tools/lint_recipes.py`（在 `codex/kitchen-model` 分支）跑出的结果：

| 问题 | 数量 | 例子 | 为什么是问题 |
|---|---|---|---|
| 要用温度计 | **73 道** | “测肉最厚处中心至少 63℃” | 家里一般没有探针温度计。这句话等于没给判断方法 |
| 模板句重复 | 40 道，92 处 | “加剩余油炒姜，放海鲜、20 毫升水和生抽加盖煮熟”出现在 5 道菜里 | 鲍鱼、章鱼、鱿鱼的做法完全一样，不对 |
| 泛称食材 | 12 道 | 步骤里写“海鲜”，不写“鱿鱼” | 跟做时用户要自己猜 |
| 单独的卫生步骤 | 14 道 | “处理生海鲜后洗手并清洗刀板” | 占掉一整步，要多按一次 OK |
| 难度标错 | 13 道 | 冬瓜焖鲍鱼、白切鸡标“适合新手” | 新手被劝退 |
| 组合式菜名 | 6 个前缀 | 番茄×22、香菇×16、青椒×12、冬瓜×9、西兰花×9、洋葱×9 | 抽菜时总是“番茄 X”“香菇 X”，显得单调 |
| 家常经典缺失 | 约 37 道 | 回锅肉、鱼香肉丝、宫保鸡丁、糖醋排骨、咸蛋蒸肉饼、蛋炒饭、皮蛋瘦肉粥、煲仔饭、手撕包菜、地三鲜…… | 候选菜单里有，却没做；反而做了番茄三文鱼汤、洋葱炒章鱼这类不常见的组合 |

另外，菜系 130 道是“家常”、川菜 1 道、湘菜 1 道；主食只有 2 道。

**建议（D2 菜谱质量版）**：

1. 删掉或替换约 40 道组合菜（名单由刘东坡定），换成候选里的经典菜。新菜需要补菜图：每张约 11 KB，资源区还剩 1.49 MB，放得下。
2. 所有菜谱统一按 `RECIPE_FORMAT.md` 的写法重写：
   - 熟度判断改成看和摸，例如“鸡腿扎筷子流出清汁”“虾身弯成 C 形、全部变红”。
   - 卫生提醒并进第一步。
   - 步骤里写具体的食材名。
   - 重新评定难度。
3. 每道菜至少有一个“不同于其他菜”的关键步骤。lint 的模板重复率要从 18% 降到 5% 以下。
4. 这一轮由 Claude 改写，刘东坡在厨房抽查。改完后由 Codex 重新打包 KRC，只需要刷资源区。

## 4. 仓库和协作

**现状**：

- 7 个分支，其中固件分支和设计分支是**两套没有共同祖先的历史**。
- main 只当“入口”用，最新内容在 `codex/kitchen-model`，最新固件在 `codex/release-v0.1.0`。
- `HANDOFF.md` 有 289 行，11 个“最新状态”块互相覆盖。
- `.git` 已有 320 MB。

问题：新来的人（包括另一台电脑上的 Codex）要先读完长篇交接，才知道该切哪个分支。规格文档和实现也已经不一致：AGENTS 还写着“小智加厨房”，README 还在宣传语音“下一步”。

**建议（需要刘东坡同意后执行，不影响已发布的东西）**：

| 动作 | 效果 |
|---|---|
| 把 `codex/kitchen-model` 合并进 `main`（它从 main 分出；main 之后只改过 HANDOFF 和 README，合并只会在这两个文件上冲突） | main 重新成为设计、内容、美术的唯一主线 |
| 固件固定在一个长期分支 `firmware`（从 `codex/release-v0.1.0` 改名），或者拆到独立仓库 `nabo-kitchen-firmware` | 不再有“哪个运行时分支才是最新”的问题。v0.1.0 tag 和社区源码链接保持有效 |

## 6. 容量

| 项目 | 大小 | 说明 |
|---|---|---|
| 应用 | 514,704 B / 1.94 MB 分区 | 很宽裕 |
| 资源包 | 3,756,062 B / 5 MB 分区，**剩 1.49 MB** | |
| ├ 菜图 | 1,596,273 B | 144 张完整菜图，平均约 11 KB |
| ├ NABO 动画 | 1,019,522 B | 4 个动作。再加 8 个动作需要约 1.5 MB，**放不下**，要先压缩（降到 160 px、减少帧数、帧间差分） |
| ├ 字体 | 966,933 B | 3500 常用字加多字号。可以考虑把 15/20 px 合并成一个字号，省约 200 KB |
| └ 菜谱、图标、界面 | 约 170 KB | |
| 模型容量 | 192 道菜 | 超过要改模型。`experiments/krc_stream/` 有 1000 道菜的流式读取实验 |

**结论**：菜谱扩到 192 道没问题；补齐 NABO 动画前要先压缩动画和字体。
