# 架构

本文定下厨房版的系统结构、存储预算、数据流和对外接口。具体数值以实测为准，标了“待实测”的地方在 M4 开工时先测。

## 1. 硬件和基线（必须遵守）

- ESP32-C3 单核，**没有 PSRAM，没有浮点单元**：渲染、动画、排序、计时一律使用整数或定点数。
- 8 MB Flash，分区沿用 `ai_passport_nabo.csv`：

| 分区 | 偏移 | 大小 | 厨房版用途 |
|---|---|---|---|
| nvs | 0x9000 | 24 KB | 设置、小量计数（沿用旧键，只加新键） |
| phy_init | 0xf000 | 4 KB | 不动 |
| factory（app） | 0x10000 | 0x3f0000（3.94 MB） | 小智加厨房的程序 |
| assets | 0x400000 | 3 MB | 只读：NABO 动画、菜品图层、图标、字体、精选菜谱库 |
| files | 0x700000 | 1 MB | 可写：用户菜谱、做菜记录、收藏、图鉴进度 |

- **基线估算**：电台版在删掉牌桌和跳一跳、还没加入电台素材时测到：app 3,334,112 B（剩约 776 KB），assets 1,324,917 B（剩约 **1.82 MB**）。厨房版从同一个基线分出，所以厨房能用的大约是 **assets 1.8 MB、app 700 KB 以上，再加 files 分区 1 MB**。分出仓库后要用实际构建结果重新核对。
- 运行内存：厨房页打开时总占用要控制在 45–60 KB。退出后，空闲堆要回到 60 KB 以上、最大连续块 30 KB 以上，留给小智的 TLS 和 Opus。

## 2. 固件仓库怎么来

`ai-passport-nabo-xiaozhi-kitchen` 从**牌桌版 v1.6.0**分出。这是最后一个经过实机验证的版本，电台版也是从它分出来的。分出后的处理：

1. 删除牌桌、谁是卧底、跳一跳，以及它们的素材、测试和生成器（做法参照电台版的 `2008f4e`）。
2. 保留：小智、NABO 主界面和菜单、设置、`panel_borrowed` 屏幕保护、音频所有权切换、按需创建的菜单面板。
3. 板型身份 `ai-passport-nabo`、分区表、NVS 旧键全部不变，用户可以用 upgrade 模式在各版本之间切换。
4. **不能退回的修复**都列在 nabo-passport-game skill 第 3 节，改动前逐条对照。

## 3. 模块划分

```
main/nabo/kitchen/
  kitchen_model.c      纯逻辑：抽菜、搭配、去重、冰箱匹配、买菜单、等级（不依赖屏幕、声音、RTOS）
  kitchen_recipes.c    菜谱库读取：assets 中的 KRC1 包 + files 分区的用户菜谱，统一成同一套接口
  kitchen_store.c      files 分区读写：记录、收藏、图鉴、用户菜谱；原子写入（先写临时文件再改名）
  kitchen_timer.c      计时器服务：最多 3 个，基于 esp_timer，不依赖页面；离开厨房也能继续计时
  kitchen_dish.c       菜品合成：器皿、汤汁、食材、点缀分层叠加，输出 160×120 的显示列表
  kitchen_gfx.c        显示列表加脏矩形、8 行条带送屏（沿用牌桌和电台的做法）
  kitchen_sprites.c    NABO 动画解码（调色板加差分帧，直接从 Flash 读取）
  kitchen_view_*.c     每个页面一个文件：home / draw / result / steps / timer / fridge / shop / book / settings
  kitchen_audio.c      提示音合成：滋啦、敲锅、计时铃、盖章
  kitchen_voice.c      本地语音命令匹配（经 Board::HandleRecognizedSpeech）
  kitchen_mcp.cc       MCP 工具 self.kitchen.*
```

每个文件控制在 400 行左右。`kitchen_model.c` 要能在宿主机上用 ctypes 编译，和浏览器原型逐步对拍。

## 4. 两种运行模式（最大的架构风险）

现有游戏打开时会**停掉小智、独占音频**。但在厨房里，最有价值的是手不碰工牌时能用语音操作，所以厨房版需要两种模式：

| 模式 | 什么时候用 | 小智 | 画面 | 声音 |
|---|---|---|---|---|
| **A 本地模式** | 抽菜、冰箱、图鉴、买菜单 | 停止（和其他游戏一样） | 完整 NABO 动画 | 本地 16 kHz 合成音效 |
| **B 边做边聊** | 跟做和计时页（可选开启） | **保持运行** | 精简：步骤卡片加 NABO 小头像，不播大动画 | 借用小智的播放通道播提示音 |

模式 B 有两条实现路线，**M4 第一件事先做验证（spike）**：

1. **MCP 路线**：大模型听到“下一步”，调用 `self.kitchen.step_next`。稳妥，但需要联网，而且每一步都走一次云端。
2. **本地匹配路线**：小智的语音识别结果先经过 `kitchen_voice.c` 匹配“下一步、上一步、还剩多久、计时 N 分钟”等固定短语，命中就在本地执行，不送大模型。

验证要测的数据：模式 B 下的空闲堆和最大连续块、小智对话是否稳定、屏幕和小智界面会不会争用。如果内存不够，模式 B 降级为“只有步骤卡片和计时”。**v0.1 只做模式 A**，模式 B 放到 v0.4。

工牌是否支持免按键唤醒，要在固件里核实（esp-sr 是否启用唤醒词）。如果不支持，模式 B 就是“按 OK 说话”。

## 5. 存储布局

### 5.1 assets 分区（只读，随固件更新）

| 文件 | 内容 | 预算 |
|---|---|---|
| `kitchen_nabo.bin` | NABO 吧台动画，约 12 个动作 | 700 KB |
| `kitchen_dish.bin` | 器皿、汤汁、食材熟料图层、点缀 | 200 KB |
| `kitchen_icons.bin` | 食材图标、火候和做法图标、NABO 小头像、徽章、界面套件 | 120 KB |
| `kitchen_bg.bin` | 封面、吧台、黑板等背景 | 120 KB |
| `kitchen_hero.bin` | 招牌菜精绘图，先放 30–60 张 | 250 KB |
| `kitchen_recipes.krc` | 精选菜谱库，300 道起 | 150 KB |
| 字体子集 | 标题霞鹜文楷，正文思源黑体 16 px 2bpp，覆盖《通用规范汉字表》一级字 3500 个 | 300 KB |
| **合计** | | **约 1.84 MB**，接近上限，见 5.3 |

### 5.2 files 分区（可写，upgrade 时保留）

```
/kitchen/user_recipes/<id>.json   小智存进来的菜谱，每道 ≤ 2 KB，上限 200 道
/kitchen/history.bin              最近 60 次做菜记录：菜谱 ID 哈希 + 日期
/kitchen/state.json               收藏、图鉴位图、连续天数、累计道数、等级、今日抽签种子、剩余重抽次数
/kitchen/shopping.json            当前买菜单
```

**待核实**：分区表注释写着“保留原 files 区域”，要先确认原厂或小智有没有在用这个分区、用的是什么文件系统（SPIFFS 还是 LittleFS），否则可能和厨房数据冲突。如果不能用，退回的方案是：用户菜谱放进 NVS 的单独命名空间（容量小很多，上限约 30 道），或者从 assets 分区里划出一块。

### 5.3 预算超了怎么办（按顺序减）

1. 招牌菜精绘图从 assets 移到 files 分区，作为“扩展图包”。
2. NABO 推荐动作降到 8 帧，或者删掉可选动作。
3. 正文字体从 2bpp 降为 1bpp（省一半，但字边缘会有锯齿）。
4. 不能减：菜谱数量（文字很便宜）、核心动画（待机、颠勺、端盘、守锅）。

## 6. 菜谱库

- **源格式**：`data/recipes/*.json`，一道菜一个文件，规则见 `data/RECIPE_FORMAT.md` 和 `data/schema/recipe.schema.json`。
- **构建**：`tools/pack_recipes.py` 做三件事：用 schema 检查每道菜；把食材、做法、汤汁等字符串换成编号；文字用 heatshrink 压缩，打包成 `kitchen_recipes.krc`。

```
KRC1 头 | 索引表（每道菜 16 B：ID 哈希、分类位、标签位、用时、难度、主料位图偏移、数据偏移）| 主料位图区 | 压缩正文区
```

  索引表常驻 Flash，抽菜和冰箱匹配只扫描索引表，不需要解压正文。打开某道菜时才解压它的正文，最多 2 KB 缓冲。
- **字体缺字**：打包时统计所有用到的字，凡是不在字体子集里的字都直接报错。小智保存的用户菜谱在写入前也做同样的检查，有缺字就让 MCP 返回错误和缺的字，请大模型换个说法。
- **用户菜谱**：同一套 schema，在设备上以 JSON 存储，用 cJSON 解析（小智已经包含这个库）。

## 7. 推荐算法（规格，原型实现，固件对拍）

- **随机数**：mulberry32。每天的种子由日期和设备序号算出，所以当天重新打开工牌，抽到的还是同一道菜，想换只能用重抽次数（默认每天 3 次）。没有联网、拿不到日期时，用开机计数代替。
- **过滤**：分类和搭配、人数（只用于换算用量）、可用时间，冰箱模式下还要看食材。
- **权重**：
  - 基础 100
  - 3 天内吃过 ×0.1，7 天内 ×0.4，14 天内 ×0.8
  - 收藏 ×1.5；当季 ×1.3；“想试试”标签 ×1.2
  - 难度高于当前设定的 ×0.5
  - 全部用整数计算，乘法按百分比再除以 100
- **搭配**：一荤一素一汤要满足三个条件：三道菜的主料不重复；烹饪方式不全一样（例如不会三道都是炒）；总用时不超过设定值。如果找不到，就放宽一条约束，并在界面上提示。
- **冰箱匹配**：得分 = 已有主料数 / 需要主料数，调料一律视为家里有。全部齐全的排前面，只缺 1 样的标为“缺 1 样”，缺 2 样以上的不显示。

## 8. 对外接口

### 8.1 按键（遵守系列约定）

| 键 | 单击 | 双击 | 长按 |
|---|---|---|---|
| UP | 上一项或上一步 | 返回上一级 | 回小智 |
| DOWN | 下一项；结果页上是“换一道” | — | 跟做页上查看用料 |
| OK | 确认；跟做页上是下一步 | — | 计时页上开始或暂停 |

跟做和计时页**不屏蔽**双击 UP（返回），因为这两页不是对局，误触返回也不会丢东西：进度会保存，回来可以接着做。

### 8.2 MCP 工具（`self.kitchen.*`）

| 工具 | 作用 |
|---|---|
| `open(page?)` | 打开厨房，可以直接跳到抽菜、冰箱或买菜单 |
| `suggest(people?, minutes?, combo?, have?[])` | 按条件抽菜，返回菜名和 ID，屏幕同步显示结果 |
| `recipe_get(id)` | 读取一道菜的完整内容，给大模型回答“这道菜怎么做” |
| `recipe_save(recipe_json)` | 保存用户菜谱，先做 schema 检查和缺字检查 |
| `step_next / step_prev / step_status` | 跟做时翻页、查询当前步骤 |
| `timer_set(seconds, label) / timer_list / timer_cancel(n)` | 计时器 |
| `shopping_add(items[]) / shopping_get` | 买菜单 |
| `stats` | 等级、做过多少道、连续天数 |

同时更新 `self.apps.open` 的程序名列表和中文别名（“厨房”“做饭”“今天吃什么”）。

### 8.3 本地语音命令

“打开厨房 / 今天吃什么 / 下一步 / 上一步 / 还剩多久 / 换一道 / 计时 N 分钟”。要能拒绝否定句、问句和同时提到多个程序的说法，测试用例写进 `test_voice_commands.py`。核心层只通过 `Board::HandleRecognizedSpeech()` 调用，**不要在 `application.cc` 里写死关键词**。

### 8.4 串口诊断

`>kitchen.status`、`>kitchen.capture`、`>kitchen.inject <key>`、`>kitchen.seed <n>`、`>kitchen.reset_test`。脚本测试必须开启测试抑制模式，**不能写入用户的做菜记录和图鉴**。

## 9. 渲染

- 绕开 LVGL 直接画屏：显示列表加脏矩形，8 行条带送屏。直绘期间保持 `panel_borrowed`。
- **菜品合成**：器皿、汤汁、食材（最多 4 层）、点缀，都按 160×120 的盘面坐标叠放，每层带偏移量。全部是索引色，透明索引为 0，叠加时不做 alpha 混合；半透明的边缘在打包时预先和**吧台木色**混合。图鉴缩略图在运行时把合成结果按 2:1 缩小，不另外存图。
- **蒸汽、火苗、飞出的菜**：由程序画粒子，不画进素材。
- 帧率目标：动画页 24–30 fps；步骤卡片页是静态画面，只在计时数字变化时重画。
- 宿主测试用 C 渲染代码输出 PNG，和原型对照；增量重画和整屏重画必须逐像素一致。

## 10. 声音

- 本地模式：16 kHz I2S，worker 每 20 ms 调一次 `kitchen_audio_fill(samples, 320)`。界面音量 100% 时也要留余量，不能满幅输出。
- 音效优先用程序合成：滋啦（滤波噪声）、敲锅（金属 FM）、计时铃（双音铃）、盖章（低频闷响）。实在不像，再用 16 kHz 的短采样，每个不超过 0.6 秒。
- **计时铃必须在抽油烟机开着时也听得见**：铃声要用 2–4 kHz 的强分量，重复 3 次，并且屏幕同时闪烁。这一项需要真机实测。

## 11. 测试与验收

- 宿主测试：`test_kitchen_model.py`（和原型对拍）、`test_kitchen_recipes.py`（打包后逐道解回来比对）、`test_kitchen_dish.py`（合成渲染）、`test_kitchen_store.py`（掉电时写入中断能恢复）、`test_voice_commands.py`。
- 真机验收：完整做一道菜（包括计时）；同时开 3 个计时器；离开厨房回到小智后计时还在走、时间到会响；10 轮进出厨房的压力测试；退出后和小智正常对话；油烟机开着时能听见铃声。
- **构建成功不等于真机验证通过**。验证摘要写进 `validation/vX.Y.Z.json`，并绑定 app SHA256。
