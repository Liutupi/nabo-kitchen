# 浏览器原型（M1）

## 当前开发版：v0.2（2026-10-30）

当前实现以 `DESIGN.md` 第 8 节的去日期规则为准：按做饭次数降权，菜单跨重启保留，重抽不限次；本节以下的 M1 日期/次数限制说明仅是早期冻结记录。

首页有常驻“计时器”入口，用 UP/DOWN 选中后短 OK 打开；从默认焦点短 UP 一次也能选到它。运行、暂停、未确认到时和空计时状态均可进入，无需重新打开原菜谱。P7 长 OK 暂停/继续、长 DOWN 取消选中项，双 UP 返回首页；取消不删除步骤进度或重新启动该步骤计时。重新加载后原运行计时恢复为暂停，再从首页进入管理。

入口、返回、暂停/取消和重载恢复都由真实键盘/浏览器测试覆盖；固件与实体工牌验收分别记录在 main `HANDOFF.md`。

## M1 冻结说明

从仓库根目录运行 `node prototype/server.mjs`，打开 [本机原型](http://127.0.0.1:4173/)。也可在命令最后指定端口。需要 Node.js；本次验证使用 v24.19.0。仅绑定本机，不依赖网络、CDN 或 npm 运行依赖。服务器启动后，每次加载页面都会枚举 `data/recipes/curated/*.json`；当前菜单内容和所有图层均读取仓库真实文件，不复制占位菜谱。

画面逻辑尺寸为 240×320。桌面大屏仅整体放大；窄屏保持原尺寸。点击画面和下方实体按钮均可操作；键盘为 ↑、↓、Enter/空格。长按门槛 650 ms，双击 UP 间隔 280 ms。第一下短 UP 延迟派发，双击原子返回；长按释放不再补发短按，键盘重复事件不当成双击。切换到别的键会先派发待定短 UP，不丢操作。

## 页面与状态

P0–P13 均实现。首页、条件、单菜/四菜结果、用料、跟做、三计时、完成、冰箱、推荐、买菜单、图鉴和设置都可走通。条件、冰箱、收藏、买菜单、步数、已走步骤、计时启动标记、最近60次历史、累计解锁/次数、连续天数、每日种子与重抽次数保存在本机 localStorage。累计统计和连续天数独立于60条历史窗口，避免记录裁剪丢失进度。保存失败在画面上提示。

- P1 长 OK 使用记住的条件；当天同条件再次打开沿用同一结果。首次抽签不扣重抽，后续换菜或更改条件重新抽均扣次数，不能靠改人数绕过上限。新的一天重置每日次数，不重置做菜进度。
- P4 单菜 UP 回首页，双 UP 回上级；搭配 UP 选上一道、DOWN 重抽整组、OK 打开选中的菜。四道搭配保留全部四个 ID，三张72px卡片的视口随焦点横向滚动。P4 按批准的样板不叠加底栏，避免遮住 y284 的 OK 行。
- P5 DOWN 把食材加入买菜单，按相同食材和单位合并；已买项沉底，可清空。长 DOWN 翻用料页、UP 往回翻，长清单也能只用实体键读完。用量按人数和源菜谱份数换算到百分位；“5+”以5人为计算基数。数字开头的调料用量同步换算，“适量”等原文保留。
- P6 OK 标记当前步骤已走并前进；计时步骤第一次 OK 启动计时，第二次 OK 才前进。UP 上一步、双 UP 返回、长 DOWN 看用料，均保留进度。长文字在18px卡片内滚动，短 DOWN 先滚文字，到底后进入计时页；点击计时胶囊也可进入。只有全部步骤均已走完，最后一步 OK 才记完成，同一会话重复确认不会重复计数。
- P7 UP/DOWN 切换，长 OK 暂停/继续，到时短 OK 确认并释放槽位。最多3个**总计时器**，包括运行、暂停、未确认到时项。服务与页面独立，返回首页、回小智的原型外部状态、重新加载页面都继续计时；页面外也显示到时横条，OK 跳 P7。到时边框闪3次。此原型默认静音，无音效输出。
- P9 为 v0.1 的30个食材，四分类、每页8个40px图标；UP/DOWN 跨分类连续移动，点分类可跳转。长 OK 进入最多10项的推荐列表。P12 图鉴按新版72×80卡片采用3列、2个可见行滚动，覆盖旧版3×3的尺寸冲突。
- P13 设置保存声音、音量、1–5次重抽、忌口、口味偏好、难度；清空做菜记录先进入操作，再连续确认两次，UP/DOWN/返回取消。清空范围为历史、图鉴计数、连续天数和跟做进度，保留收藏、冰箱、买菜单与设置。少辣/少油只存储偏好；规格未定义菜谱标签到这两项偏好的确定过滤/加权映射，本模型不自行增加权重或把它们当忌口。周挑战仍按规格留至 v0.3。

## 推荐模型与 C 对拍 API

2026-10-28 产品决定：**历史只降低权重，7天内仍可再次抽到**。没有历史硬过滤，也没有虚假的“放宽7天去重”关卡。结果页显示近期做过的日期标签。

`model.mjs` 是纯模块，Node 和浏览器使用同一份。`mulberry32(seed)` 每次返回 uint32；抽签取 `nextUint32 % sumWeights`。每日种子为日期字符串、竖线和设备序号的 FNV-1a32；重抽第 n 次使用 `(dailySeed + n * 0x9E3779B9) >>> 0`。日期不可得的设备开机计数回退留给固件层，此浏览器使用本机日期。

权重按此顺序每步整数截断：基础100；距上次做菜0–2天乘10%，3–6天40%，7–13天80%；收藏150%；当季130%；“想试试”120%；高于难度设定50%。最低1。多道组合以各菜权重相加抽取，候选按稳定的源文件/角色遍历顺序生成，相同 ID 集合去重。硬约束始终保留忌口和组合内不同菜谱 ID；人数仅用于用量。主料重叠、做法相同、总用时依次放宽，界面只提示所选结果**实际违反**的约束；缺少类别时直接说明无法组成搭配，不编造或重复菜谱凑数。做法取排除切/拌/腌/焯后的最高频做法，同频按方法 ID 排序。

冰箱只比较 `main:true`：得分为整数 `已有主料数*1000/所需主料数`，只显示缺0或1种主料的菜，调料不参与匹配。忌口始终排除。重抽有其他可选组合时避免与当前完整 ID 集合相同。

浏览器 `window.kitchenTest` 提供 `snapshot()`、`dispatch(key, kind)`、`recommend(conditions, context, seed, avoid)` 以及 `model` 的全部纯函数。`?test=1` 使用独立存储键，额外开放 `reset(overrides, clockMs)`、`visit(page,id)`、`showResult(ids)`、`setTimer(seconds,label)`、`advanceTime(ms)`。测试时钟默认固定于 2026-10-28T12:00:00Z，只由 advanceTime 前进，刷新也保留；reset 同时重置时钟和计时 ID，避免对拍被壁钟抖动干扰。这些测试变更接口在普通模式拒绝执行。此接口供后续 C 纯逻辑逐步对拍，不表示已有 C 版本或真机验证。

## 验证与素材

运行：`node --test prototype/tests/model.test.mjs prototype/tests/ui.test.cjs`。纯模型测试使用 Node 内置测试器。UI 测试使用 Playwright 与本机 Edge，可通过 `PLAYWRIGHT_MODULE`、`EDGE_PATH` 指定位置；Codex 默认使用其打包的 Playwright。测试临时启动本地服务，静音运行，退出后关闭服务/浏览器；截图写入忽略目录 `private/prototype-qa/`。用 `?test=1` 不会写正常用户记录。

本次冻结版本的可携带验证材料在 [validation/report.json](validation/report.json)、[完整测试输出](validation/test-output.txt) 和 [页面检查图](validation/all-pages.png)，不依赖 private/。20项测试全部通过（10项纯模型、10项 Edge UI），覆盖30道菜全部步骤、P0–P13、手机尺寸触摸、四菜视口、三计时器和持久化。自动化通过后仍需刘东坡在手机上完整做一道菜，才能完成路线图的 M1 用户验收；当前未做真机测试。

浏览器内中文字体使用 `assets/kitchen-han.woff2`；字体由 T1 管线按正式字体来源和字符集生成，版权和许可声明与字体一同交付。它只用于浏览器，不能直接计入固件字库预算。Archivo Black 从仓库已有参考字体本地加载。月亮、钟表、灯泡使用程序 SVG，勾选为 CSS，星标与火候/做法使用已交付 PNG，不依赖 emoji 字形。`build_assets.py` 仅从原始 C/K2 绿幕生成裁切/抠绿的透明派生图，需 Pillow，不覆盖字体或原始图片。`assets/sources.json` 记录输入输出哈希。

Grok 视频尚未接入本浏览器；C 与 K2 是静态姿势，没有用模型逐帧或伪造视频充当动画。固件字库、RGB565索引色资源、音效、与小智并行、真实按键手感和厨房实测分别验收，不能用此原型代替。
