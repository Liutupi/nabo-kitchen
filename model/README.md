# M2 宿主模型：计时器起步

`kitchen_timer.c` 是独立于 UI、RTOS 和存储的三槽计时器核心。调用方提供同一时钟域的毫秒数；标签、来源、持久化、计时铃和设备重启后的时钟恢复仍由后续集成层实现。`kt_timer` 的二进制内存布局不是持久化格式。接口使用 32 位正整数秒、64 位毫秒，超出这些边界及 ID 耗尽时拒绝创建；这是 C 接口限制，尚未进行设备级 API 评审。

```sh
python3 -m unittest discover -s model/tests -v
python3 model/font_budget_probe.py
python3 model/benchmark_recommend.py
```

对拍直接从未修改的 `prototype/timers.mjs` 生成固定时钟的 2,029 步轨迹，比较操作返回值、槽顺序、ID、状态、剩余时间、到期时间与确认状态。覆盖容量、暂停、到期、提醒、取消以及模拟序列化恢复；两项独立变异测试验证容量和到期错误可被检测。模拟恢复仅验证模型字段与原型行为，**不验证掉电持久化、时钟同步、按键或音频**。

`kitchen_model.c` 实现 mulberry32 和单菜权重，分别对照原型的 500 次随机数输出和 160 组权重边界/标志组合，变异测试检出错误权重。权重函数的调用者负责计算最近有效历史的天数、季节和收藏等标志。

`kitchen_recommend.c` 实现单菜、两至四道搭配、忌口、组合去重、三档放宽、避免重复重抽及加权抽签，无堆分配。168 个场景和原型对拍，包含真实 30 道菜、多类别、非主料忌口和重复主料；变异测试覆盖忌口、重抽、组合去重和做法放宽。输入由调用方按原型的稳定顺序提供，负责将全部食材和主料映射到同一张 64 位表、标记同菜重复主料、计算原型的主要做法及权重。输入错误返回 `KR_INVALID`。

当前接口上限为 **64 道菜、64 种食材**，这是为现阶段候选实现设置的边界，不满足架构中未来数百道菜或动态扩展的目标；大库必须重新设计或扩展并测时，不能静默截断。`benchmark_recommend.py` 在宿主机使用合成的所有菜可担任所有角色、所有约束均需放宽的场景测量，非 C3 数据。这个搜索仍有组合增长，不能放进按键回调中阻塞运行；实际资源适配、执行时间和任务栈尚未测量。冰箱、按键、会话、保存和界面状态仍未移植，M2 尚未完成。
